## 1. 结论与推荐路线

**优先验证 GOST v3 受控接入；官方 frp + ser2net 为组合备选；仍不适配时才评估扩展现有 C++/Go Tunnel。现在不直接定型，也不同时实现多个后端。**

GOST 官方文档分别提供 TCP/UDP 远程转发、串口重定向和动态服务管理（S1～S4），功能覆盖最接近本次需求。但是，“组件有这些能力”不等于“组合后满足本项目生命周期”。串口 UDP、强制关闭已有连接、会话失效后禁止自动重连、旧 ARM/uClibc 运行和资源消耗，均尚未实测。

任何方案都必须增加平台侧条目管理、租期、设备会话绑定、目标校验、串口枚举、状态/API/事件与WPF页面；**没有已经证明可以无缝接入本仓库的成品**。现成方案节省的主要是数据转发实现，不是产品业务层。

推荐先批准本文产品语义和有限PoC；PoC输出固定版本、真机数据、兼容矩阵、撤销证据与最终选型，再进入正式实现。GOST若只是串口配置不足，先评估配合ser2net；若根因是Go运行时、进程体积或资源不适配，不盲目再试同类组合。

## 2. 需求解释与可观察完成条件

### 2.1 内网穿透

1. WPF选中一台已纳管且在线的Probe设备，进入“内网穿透”页面；这里“本机同网段”解释为**所选Probe的直连接口网段，不是Windows电脑所在网段**。
2. 选择接口/广播域、目标IP、目标端口、TCP或UDP、有效期，创建一条映射。第一条需求中的“开启串口透传”按“开启内网穿透”理解；串口在独立页面处理。
3. 目标IP既可手输，也可从现有LAN下接/本机广播域快照中选择。没有IP的记录不进入选择器；同接口+同IP去重，保留两种来源标签。重叠子网或多接口同IP不得跨接口合并。
4. 邻居清单是候选而非在线证明；显示采样时间和过期提示，不因未发现而阻止合法手输。创建时Probe重新检查目标是否位于所选接口的当前直连子网，不把IP前三段相同当作同网段。
5. 每条为一个固定IP+端口+协议，返回Server对外主机名/IP及自动分配端口。协议选择“TCP+UDP”如需提供，应创建两条独立记录，不隐式承诺共用同一个数字端口。
6. 外部设备无须安装本平台客户端，使用普通TCP/UDP访问。UDP没有TCP式连接，需要按来源地址和端口保存有界回包关联。
7. 本轮建议首先支持IPv4直连单播目标；IPv6链路本地作用域、多网段、广播/组播发现透传不是隐含能力，IPv6扩展范围由本次审核确定。
8. 同一Probe允许多条不同映射；旧维护仍保持一个未释放Maintenance，互不取代。

### 2.2 不改默认网关与SNAT的准确含义

拟采用应用层全代理：外部设备 → Server公网端口 → 独立隧道 → Probe从所选LAN接口主动访问目标 → 回包按隧道返回。

例如（示意，不是本轮测试）：Probe `192.168.5.222/24`，目标 `192.168.5.100/24`，目标默认网关为 `192.168.5.1` 或未配置。Probe以 `192.168.5.222` 为源访问目标，目标把回包直接发给同网段的Probe，不必把默认网关改成Probe。该建议由Linux本地socket绑定语义（S10）及同链路地址条件推导，仍需目标设备实测。

- 用户可见选项命名建议为“由所选设备代理访问（无需修改目标网关）”；不要显示成已经添加iptables SNAT。
- 目标所见来源为Probe LAN IP，不保留公网访客源IP。不注入PROXY protocol或其他头破坏原始设备协议。
- 前提：双方地址/掩码匹配、二层可达、目标服务监听且ACL允许；Probe仍必须能连接公网Server。该模式不修复VLAN隔离、错误掩码和目标自身防火墙。
- 不修改iptables/nftables、转发开关、桥/VLAN和默认路由；源地址绑定与出口检查在Probe/后端适配内完成。
- 若真正需要原始IP包转发、保留客户端源IP、目标主动回连另一个端口或透明整网访问，则是另外的路由/NAT方案，不能称作这次单端口代理已经支持。TCP协议载荷中另行协商的动态端口也不自动穿透。

### 2.3 串口透传

1. 从所选Probe枚举其当前串口，不是枚举Windows COM。返回设备节点、显示名、驱动/USB身份（有则显示）、参数能力与可用/占用/权限不足/未知状态。
2. 以真实驱动和字符设备识别UART/USB串口；不把所有 `/dev/tty*`、虚拟控制台或任意文件列为串口。列表刷新不打开串口，避免切换DTR/RTS造成设备复位；真正打开和独占检查只在创建阶段完成。
3. 默认排除已识别系统console/getty/调制解调器业务口；不自动杀占用进程。占用判断可能存在竞态，必须在实际打开时复核；无法确认时不能显示“空闲”。
4. 创建参数包括串口、波特率、数据位、停止位、校验、流控、TCP/UDP和有效期；默认建议9600/8/N/1/无流控，按硬件/后端能力禁用不支持项，不静默降级。RS-232/TTL电平依赖硬件；RS-485方向控制要单列能力及实机验证，不宣称软件可任意切换物理标准。
5. TCP为原始二进制字节转发，不做字符编码、换行替换、Telnet协商或Modbus协议转换。串口读取使用原始模式；网络EOF不照搬TCP双socket的shutdown语义。
6. 默认每个物理串口只有一条活动映射、一个外部读写客户端，第二客户端拒绝；防止多个写入者混流。TCP+UDP不能同时占用同一串口。
7. 将用户“类似内网穿透”保守解释为串口也覆盖TCP/UDP，不能因为现成组件缺失而悄悄删掉UDP。
8. 串口UDP需独立约定：首个允许来源的数据报获取临时独占权，后续串口返回仅发给该IP:port；其他来源拒绝，不用“最后一个发包者”抢占回包。建议来源空闲60秒释放；首次来源出现前的串口数据不无限缓存、不广播；超时后重新建立关联。
9. 串口没有消息边界。建议UDP输出使用“可配置串口字节间隔 + 最大报文长度”的分包方式，初始建议20ms/1200字节，PoC按波特率与真实协议校准；输入数据报按接收顺序写串口，不增加自定义头。明确可能丢包、乱序，不能保证一次read或一次UDP等于一帧设备协议。不适合要求精确帧时序的协议时，应选TCP或另议协议适配。
10. 串口本身没有客户端身份，迟到数据在旧拥有者退出后可能落入新会话；关闭时清理本地缓存并设置交接静默窗口，具体窗口由设备协议测试确定。不能承诺解决所有物理串口迟到回包。
11. 暂不承诺Windows虚拟COM驱动、RFC2217远程改参数、Break/调制解调器控制线穿透和多客户端广播；这些不是原始数据透传的同义词。

### 2.4 时间与生命周期

| 情况 | 新穿透/串口建议语义 |
| --- | --- |
| 不填写有效期 | 默认240分钟 |
| 正整数分钟 | 按创建成功时的绝对租期到期关闭，校验时长溢出 |
| 显式0 | 无绝对到期时间，DTO的expires_at为null，UI显示“不限时” |
| 关闭WPF或切换Server | 不因管理客户端离开自动终止Server端条目 |
| 用户关闭、Probe失联/Session替换、Server重启 | 关闭入口、在途数据和串口，不自动恢复或重开 |
| 后端程序崩溃/不确定状态 | fail closed，显示失败/释放中，不能仅凭进程重启报ready |
| 无流量 | 条目不限时不等于资源无限；TCP空闲期限与UDP来源缓存期限单独显示和管理 |

0不限时不是断网不断开、持久保留公网端口或重启恢复。本提案先保留现有“跨Session不继承”的设计。如果需要断线自动恢复或开机自启映射，需要一并确认持久配置、租期重算及端口/凭据恢复机制。

**不得修改旧Maintenance零值含义**：当前HTTP API显式 `lease_ms=0` 被拒绝；省略选默认，内部Service的0选择240分钟。新资源用独立字段 `lease_minutes` 表达显式0，避免破坏旧UI和调用方。

仓库ADR-020记录过xfrpc生命周期崩溃并放弃该路线，ADR-021/022形成现有自研固定TCP维护。它不证明官方frpc也有相同故障，但明确禁止复用旧xfrpc或旧PoC结论充当本轮验证。

[邻居发现专项](NEIGHBOR_DISCOVERY.md)记录FNR100曾为Linux3.14.77；ADR-058记录Probe为ARMv7/EABI5/uClibc。它们只是兼容评估起点，不等于本轮核实过全部设备。Go官方最低要求对Go1.24及以后给出Linux3.2及架构约束，并指出嵌入式配置需要FUTEX/EPOLL（S8）；因此不能仅因uClibc就排除Go，也不能仅因内核版本够就宣布GOST/frpc可运行。

## 4. 现成方案比较

以下“成本/推荐”是基于仓库与官方资料的工程判断，未做性能排名或本设备兼容承诺。

| 方案 | 官方资料确认的能力 | 对本仓库的接入缺口 | 本次结论 |
| --- | --- | --- | --- |
| GOST v3 | TCP/UDP远程转发、串口重定向、服务动态增删（S1～S4） | 两端受控辅助进程；会话撤销/租期/端口隔离由平台补齐；串口UDP组合与流控/独占仍需验证 | **首选有限PoC**，优先配置接入而不是fork源码 |
| 官方frps/frpc + ser2net | frp映射TCP/UDP目标（S5）；ser2net提供串口网络桥及raw/RFC2217选项（S6） | Probe侧至少两个组件；动态配置、占用、强制踢连接及跨进程孤儿回收需要统一监管 | **组合备选**，不使用xfrpc；若只缺串口能力也可尝试GOST+ser2net |
| rathole + ser2net | TCP/UDP、服务token、配置热加载；HTTP配置API仍列为计划（S7） | Rust交叉工具链、串口桥与双端配置同步；热加载不等同平台撤销 | 仅在资源/兼容证据优于前两者时继续，不引用上游benchmark作真机结论 |
| socat | socket与终端桥接/termios选项（S9） | 不是本平台反向隧道与生命周期成品；动态多条、回包归属/管理仍要开发 | 适合隔离验证和串口桥备选，不作为完整产品后端 |
| 扩展已有Tunnel + ser2net，或最终termios原生串口 | 仓库已有TCP生命周期；可继续复用而非另起协议栈 | 新LAN目标、UDP封装/关联、串口生命周期与版本协商仍属自研 | **最后路线**；在现成方案失败证据明确后另行定型 |

ser2net当前维护者README明确列出libyaml、libxcrypt和gensio构建依赖（S6），因此它不是把一个小C文件直接并入Probe即可：需要核对GCC5.2/uClibc可构建性、裁剪与交付依赖，纳入组合方案成本。rathole当前README说明支持配置热加载，但HTTP配置API仍为WIP（S7）。

不以VPN/TUN/TAP或容器作为默认解法：本需求是指定端口或串口，不要求整网互通，也不应要求外部设备安装VPN客户端；这会额外引入驱动、路由和部署面。

### 4.1 GOST已识别的具体限制

- 远程串口重定向文档要求转发链末端为relay；不能把任意转发链组合都标为可用（S2）。
- 动态API更新已有service会重启该service，不能将“修改配置”包装成无损变更。删除service的文档描述不足以替代本项目“所有已接入流已终止”的测试（S3）。
- 当前查看的串口Config源码有数据位/停止位/校验字段，但RTS/DTR/XON流控字段仍为注释（S11）；UI不能承诺默认GOST完整硬件流控。需与固定发布版本对应后验证，必要时采用ser2net而不是扩大fork。
- 当前默认分支go.mod声明Go1.26.3（S12）；这是2026-09-11读取的开发分支事实，不等于本计划指定了某个正式版本。PoC必须固定release及其依赖，不能直接跟随master，也不能未经安全/兼容评估长期降级旧版来适配。
- 不把Go二进制的存在推导为依赖Docker/数据库。仅选最小所需功能；安装体积、RSS、线程/fd数量需实测。

## 5. 推荐接入结构（待PoC定型）

```text
WPF 内网穿透/串口透传
       │ 公开 /api/v1 + WebSocket
Management Application → Forwarding Service
       │                       │
       │ RMP控制（不载荷数据）   └→ 受控后端管理（仅本机API/IPC）
       ↓                                     │
Probe 会话/目标校验/串口枚举/进程监管           Server 数据后端
       │                                     ⇅ 独立数据链路
       └→ Probe 数据后端 ────────────────────┘
                ├→ 所选接口 → LAN IP:port
                └→ 已选串口（必要时经本机ser2net）

外部设备 → Server 分配的TCP/UDP端口 → 对应条目
```

### 5.1 分工和安全撤销

- 新增Forwarding Service管理资源；仅在确定复用点后提取少量端口/撤销公共逻辑，不重构整个Server或预建多后端框架。
- 推荐按设备控制Session监管辅助进程，支持多条映射；不默认每条映射启动一套重型服务。程序缺失时新能力不可用，原设备、文件、维护功能仍可运行。
- 平台唯一决定外部端口、目标和寿命。后端管理员接口仅回环/本机IPC并带随机凭据，不允许WPF直接访问，不向普通客户端返回后端配置、token和私有连接身份。
- 独立后端协议不能直接送入现有9001的RMT1监听。第三方路线需要新的受控数据监听及明确部署端口；最终端口在PoC后确定，不能占用8888/9000/9001。现有维护数据面不迁移。
- 采用成熟后端时，建议新数据链路启用其已有加密与服务端身份校验、绑定会话的凭据；这一局部变更需审核，不能等同整个平台TLS/认证已完成。
- **强制关闭必须由Server本地执行，不能依赖失联Probe收到停止命令**。后端须支持按条目/设备撤销监听、终止现存流并禁用旧凭据；若做不到，必须增加受平台控制的入口/连接门控，计入成本并重新判断是否仍是最小接入。不能偷偷退回“kill客户端就算关闭”。
- Management Server崩溃时后端不得留下公网监听；Probe崩溃时不得留下串口或自动重连的辅助程序。采用父进程死亡约束/监督和启动时清理自身残留对象，具体跨平台方式PoC验证，不停止其他用户进程。
- 创建先绑定Session并预留资源，Probe验证/串口打开成功、后端监听确认后再返回ready；失败全部回滚。关闭先阻止准入、断现有数据，再释放串口/进程资源；无法确认释放时保留closing/release_failed，不提前复用端口。
- 端口池与旧维护协调或使用明确不重叠池，记录TCP/UDP协议，释放后沿用24小时隔离。原隔离不是鉴权，超窗/重启后旧地址重用风险仍存在；不承诺永久身份隔离。
- 内存中保留有界活动/关闭记录；不默认为跨进程恢复。不限时条目仍占容量，配额耗尽明确报错，不关闭旧条目腾位置。

### 5.2 入口访问与滥用约束（必须审核）

- 新入口建议必须配置允许访问的来源IP/CIDR；“允许任意来源”需单独明确选择，UI显示风险，不把一个随机高端口当身份认证。
- 平台当前认证/RBAC未完成。部署前必须限制管理API可访问来源；如果任何人能调用创建接口和修改allowlist，数据入口白名单不能解决管理面越权。不能因为本轮不实施完整RBAC而忽略这一前置条件。
- 新能力只允许直连单播目标和确认的串口，禁止任意命令、路径和后端配置透传。禁止把功能顺带做成SOCKS/open proxy、任意互联网目标或广播放大器。
- UDP会话数、包长、队列、速率和放大回包须有界；TCP也限制连接/流量，不因不限时变成无限资源。
- 不自动在真实Server或路由器修改安全组/防火墙；部署时明确管理接口、新数据连接和公网服务端口分别需要什么规则。

## 6. API、Probe、UI改造面

### 6.1 草拟公开接口（不是当前契约）

| 接口草案 | 用途 |
| --- | --- |
| `GET /api/v1/devices/{id}/forwarding-capabilities` | 当前Session支持的TCP/UDP、目标地址族、串口参数及限额；设备不支持有明确原因 |
| 现有 `GET /api/v1/devices/{id}/neighbors` | LAN/broadcast目标候选，不新建第二套发现存储 |
| `GET /api/v1/devices/{id}/serial-ports` | 当前串口枚举快照、时间与stale；无遥测与空列表分开 |
| `POST /api/v1/forwardings` | 创建kind=lan/serial、transport=tcp/udp、目标、lease_minutes、来源限制 |
| `GET /api/v1/forwardings?device_id=...` | 活动条目及有界历史 |
| `GET /api/v1/forwardings/{id}` | 详情、状态、统计和失败原因 |
| `POST /api/v1/forwardings/{id}/close` | 幂等关闭 |
| WS新增forwardings变更通知 | 提示回查HTTP，首连/重连主动取快照 |

创建建议返回202+资源ID，状态creating/ready/closing/closed/failed；明确`listener_ready`与`target_status`不同，不用猜测UDP目标在线。网络请求不确定复用原Idempotency-Key/请求字节并查询已有资源；未确认创建结果不产生替代条目。不在活动时直接修改目标/串口参数，先关闭再创建；新资源ID和独立幂等键仅用于用户明确的新操作。

Probe新增带版本能力如forwarding_v1、serial_v1（命名待定），控制命令含创建时Session及资源身份；新消息编号在协议定型时分配，旧`tunnel`能力/固定CONNECT不能被解释成允许任意IP。旧Probe返回不支持，避免收到未知新消息导致整条控制连接断开。

若最终走原生路线，RMT1维持原样；新版本数据握手与TCP/UDP/串口类型单独协商。UDP必须长度定界、保留数据报边界和来源关联，不能对stream使用裸io.Copy冒充UDP。若跨公网使用UDP-over-TCP，应明示队头阻塞及丢包时延风险，不能宣传成原生UDP时延；PoC比较后再选传输。

### 6.2 WPF体验

沿用当前工作区、主题、字体和共享控件，在所选设备工作区增加“内网穿透”“串口透传”页，不整体重设计：

- 顶部紧凑创建表单；IP可编辑下拉，显示IP/接口/MAC/名称/来源；同网段校验失败定位到字段。
- 活动列表列出名称、类型、TCP/UDP、目标IP:port或串口、外部地址、状态、有效期/剩余时间、连接数或UDP关联数、双向字节数；未提供统计显示“未提供”，不是0。
- 详情展开：设备与接口/源IP、目标、创建/到期/关闭时间、关闭原因、释放及端口隔离状态、允许来源、后端能力、串口参数/分包策略、最近活动/错误。
- 地址仅在可用状态可复制，关闭或失败不继续提供可用入口；串口占用/权限/拔插错误可定位。详情可保留历史地址但必须标记“已失效”，不设连接操作。
- 0在输入旁明确“不自动到期，失联/重启仍关闭”；TCP流空闲回收和UDP来源超时不冒充租期。
- 创建/关闭等待态禁用重复按钮；切换设备/Server取消旧请求并防止迟到响应污染新页；快照恢复不自动重建通道。

Blazor生成器不增加每台设备的瞬时穿透条目；只有选型后确实需要随Probe部署的后端参数/能力开关时，才最小调整生成/打包链，不能把运行Session配置混进模板发布。

## 7. 逐步实施与停止门槛

### A：审核与有限PoC（已批准执行；准入结果见GOST_V3_POC）

1. 审核第2节产品语义及第5节边界；冻结测试用版本和依赖，检查发行许可/NOTICE及分发要求，不先引入产品依赖。
2. 只读盘点获准测试设备：内核、CPU/ABI、FUTEX/EPOLL、可用RAM/磁盘、串口驱动/节点、接口IP/掩码与现有服务；不读取凭据到日志，不打开系统console。
3. 在隔离端口/目录验证GOST TCP/UDP反向转发和串口；优先PTY/测试串口，再获准物理串口，不触碰生产端口80/22/23和现有Probe。
4. 验证设备网关为第三台路由器、完全不配置网关两种情形，抓取目标侧来源地址证明代理行为；同时验证错误网段/接口/掩码明确失败。
5. 做多条动态增删、关闭活动连接、会话替换、控制网络断开但数据网络仍通、Server/Probe/后端崩溃、端口隔离、旧凭据迟到重连和失败回滚。
6. 串口覆盖真实二进制、9600/115200（硬件支持时）、独占、慢读、权限拒绝/占用/USB拔插、关闭恢复；UDP验证单所有者和分包策略。不在生产串口发送未知控制命令。
7. 记录无通道/1条/8条时安装大小、RSS峰值、CPU、线程/fd、双向延迟与丢包。建议初始设备端辅助程序预算为新增RSS≤16MiB且≤测试设备可用RAM的25%、空闲CPU≤单核1%、1小时反复开关无单调资源增长；这是审核用门槛，不是性能预测，按目标硬件冻结后执行。
8. 强制撤销/孤儿清理目标≤5秒（隔离环境），连接中增删其他条目不打断已有条目。任一项不满足不能直接宣称现成接入完成。
9. 只有明确的GOST功能缺口才补试ser2net或官方frp；rathole仅在有不同兼容/资源优势时试。输出失败原因、最小补丁范围、组件数/包大小与推荐，不无限轮换方案。

**A验收后再次确认最终后端与必要的Accepted ADR；本轮计划获批不应被自动扩张为生产部署或无条件自研授权。**

### B：后端最小业务闭环

确定一个后端；完成Forwarding模型、目标/串口校验、租期0、双端生命周期、API/WS、能力协商、配额与失败回滚。先TCP LAN形成可测闭环，再UDP LAN，再串口TCP/UDP；每项都带集成测试，不先铺UI占位或多个后端空框架。

### C：WPF与必要打包

两页、候选列表、详情和错误/空态/无能力状态；C# Client DTO、事件回查和取消同步。辅助程序固定版本随新功能可选安装，自动受控启动，不要求用户手写frp/GOST配置；基础Server和Probe不依赖辅助程序才能启动。原Probe仍在10.1.1.128按ADR-058构建；47.119.168.150仅为管理/部署目标。

### D：完整回归与交付

按DEVELOPMENT运行受影响Go包、go vet/build、race、C++ CTest/sanitizers、Phase1～5真实Linux Probe回归及Windows/Linux Server、WPF构建/行为/布局和必要生成器测试。覆盖旧维护、文件传输与控制心跳在新通道负载下仍正常；老Probe/新Server、新Probe/既有服务无能力降级明确。

PoC不替代最终真实串口/目标设备验收；QEMU/PTY不替代厂商固件；缺失sanitizer库依旧列缺口，不假报通过。最终交付安装/升级/关闭/回滚说明、端口部署清单、依赖版本/许可说明和实机证据。发布、替换进程、Git提交/推送仍需当次授权。

## 8. 需要用户审核的决定

1. 是否批准“GOST优先有限PoC → 组合备选 → 最后扩展现有Tunnel”的路线，并接受新功能可选携带受监管辅助程序；不是现在确定采用GOST。
2. 是否按IPv4直连IP:端口代理落地“无需修改目标网关”，不改路由器SNAT规则；IPv6/整网透明转发另议。
3. 是否接受0仅为不自动到期，失联/Session替换/重启即关闭，不自动恢复；若需要持久通道应现在调整设计。
4. 是否接受串口默认单客户端独占、同时只选TCP或UDP、UDP首来源锁定与分包规则，不含虚拟COM/RFC2217/RS-485方向控制的隐含承诺。
5. 是否接受新公网入口来源限制、管理API网络隔离和新数据链路成熟加密作为部署前提；不把整个认证/RBAC工程纳入本次。
